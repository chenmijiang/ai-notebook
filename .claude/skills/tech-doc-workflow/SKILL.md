按任务选择最短的文档处理路径。默认由主 agent 保持上下文、做判断和修改；本 skill 不强制执行完整流水线。

## 任务路由

### 新建文档

先确认核心问题、中心主张、目标读者、文档模式、覆盖范围、非目标和初步一级骨架。用户确认后，主 agent 按需查证、起草和验证。研究结果要求改变核心问题、中心主张、文档模式或一级骨架时暂停确认；只改变章节内顺序和措辞时直接处理。

创建或结构设计时读取完整的 [`tech-docs-guide`](../tech-docs-guide/SKILL.md)。

### 结构重构

编辑前说明保留、合并、删除和新增的范围以及验证方式。中心问题、中心主张或文档模式不变时直接执行；发生变化时先确认。主 agent 负责删重、重排和最终修改。

### 局部修订

直接修改目标段落，只检查相邻论证、技术载荷和最终 diff。不启动研究或 reviewer，除非修改触及关键事实。

### 事实更新

重新核查文档内所有版本敏感事实，再修改受影响的结论和直接相关段落。稳定事实不随意重查。研究结果默认留在当前上下文；来源分散、任务可独立切片时，最多调用一个研究 subagent。

### 语言编辑

结构稳定且出现系统性翻译腔、AI 腔或绕行表达时，调用 [`tech-doc-humanizer`](../tech-doc-humanizer/SKILL.md)。局部语言问题由主 agent 直接修改。语言编辑默认不启动研究或 reviewer。

## 按需审校

主 agent 默认自行检查。只有关键事实密集、范围较大、用户明确要求独立审校，或主 agent 无法确定结构和事实时，才调用一个通用只读 reviewer。向 reviewer 提供任务范围、目标文档和已有来源。Reviewer 只返回影响正确性、范围或理解的问题；每条包含文件位置、问题和一句修改建议。不重新研究已确认事实，不修改文件，不委派其他 agent。没有实质问题时返回“无实质问题”。

主 agent 根据问题修改并检查 diff。一次处理后结束；只有新增关键事实或语义无法确定时，才定点核验。

## 验证与退出

只执行当前分支对应的验证；通过后结束，不自动进入其他分支。

- 局部修订和语言编辑：检查目标 diff、技术载荷和链接、命令、代码未被误改。
- 新建和结构重构：额外检查核心问题、章节路径、关键事实、边界、证据以及示例与结论是否一致。
- 事实更新：检查所有受影响版本敏感结论及其直接引用。
- 格式、`docs/index.md` 和 `check:home` 由仓库已有 hook 或命令负责；本 skill 只核验结果，不重复执行。

## 原则

默认不调用 subagent；需要时每类最多一个研究或 reviewer，且 subagent 不得继续委派。中间状态按需保留在当前上下文，不强制生成范围卡、证据地图、断言位置表或完整问题协议。
