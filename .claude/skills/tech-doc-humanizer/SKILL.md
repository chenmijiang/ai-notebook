直接润色 `docs/` 中结构稳定的中文技术文档。只改语言，不研究事实或重构章节。

## 触发与范围

用户要求润色、去翻译腔、去 AI 腔或精简绕行表达时使用；同类问题至少出现三处，或跨两个一级章节时，主 agent 也可调用。局部问题由主 agent 直接修改。

通读全文；用户指定章节或行号时，只编辑指定范围。

## 结构门槛

出现以下任一情况，停止编辑并报告位置：

- 两个章节完整解释同一结论，无法判断保留哪处；
- 同一术语前后含义冲突；
- 章节职责重叠，改写会改变论证路径。

普通长段落、局部绕行和非相邻重复不阻塞。跨段重复只报告，不自行删改。

## 保持不变

保持代码块和行内代码、命令、标识符、API 名称、URL、链接目标与锚点、版本号、数值及单位、原始引用中的技术表述不变。

不得改变技术事实、条件、否定、例外、因果关系或来源含义；不查源码，不补充事实。无法确认语义等价时保留原文并标记。

标题、正文、表格、列表和代码注释可编辑。

## 改写

每句写清条件、动作和结果。优先：

1. 删除无信息增量的铺垫和模板化衔接；
2. 用动作、条件和结果替换抽象名词化表达；
3. 拆开多重条件、例外或转折，并让限定紧邻结论；
4. 先写结论，再保留必要机制和边界；
5. 合并相邻同义句，删除未新增机制、边界或实践后果的复述；
6. 用具体判断代替宣传性评价、机械排比和模板化总结；
7. 同一概念使用同一术语。

不注入第一人称、个性、幽默或题外话。

## 完成

确认修改范围内不再有同类系统性语言问题，且每处改动都减少绕行、翻译腔、模板痕迹或局部重复。确认未新增事实、章节、论证分支或文件外改动。

简短返回：改写范围、保留的技术疑点、发现的跨段重复位置。不要评分、复述全文、调用 reviewer 或其他 skill。
